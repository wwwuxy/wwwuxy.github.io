## 存储模型：
内存架构及其访问权限：
![GPGPU 笔记配图 20260325165013](/images/notes/gpgpu/20260325165013.png)
![GPGPU 笔记配图 20260325165618](/images/notes/gpgpu/20260325165618.png)
- 每个SM上有大量寄存器资源，寄存器资源会分到每一个线程使用
- 局部寄存器是线程私有的 --> 实际存储在全局寄存器中，用L1 L2 Cache进行访问优化
- 共享存储器是 线程块内所有线程 共有的 --> 往往与 L1 公用一个片上存储空间
- L1 Cache 内是全局/局部存储器的数据缓存，若L1 miss，则会进行 合并访存（合并尽可能多的线程访问请求）
- 全局存储器位于设备端，所有的线程均可访问，但是时延较大
- 常量存储器位于设备端，容量较小，可以缓存在SM的常量缓存中，只读属性
- 纹理存储器位于设备端，针对2D空间局部性进行了优化
- 主机存储器分为 可分页内存（malloc、new分配，可被分配至虚拟内存） 和 锁页内存（仅分配至物理内存）

## 通信模型：
- `__syncthreads()`同一线程块内线程同步（在pc位置添加栅栏） --> PTX 中的bar
![GPGPU 笔记配图 20260326164634](/images/notes/gpgpu/20260326164634.png)

- `__threadfence()、____threadfence_block()、__threadfence_system()`表达对存储器访问结束
- `cudaDeviceSynchronize()`停止CPU端线程的执行
- 协作组（`thread_block`），将不同粒度和范围内的线程重新构建一个组，在协作组的基础上构建同步和通信 --> 软件和运行时支持，非硬件支持
	- 线程束内部线程合并分组
	- 线程块分块
	- 线程块组
	- 线程网格组
	- 多GPGPU线程网格组
	- 线程洗牌：允许某个线程读取其他线程的寄存器
	- 线程表决：对组内的每个线程的谓词寄存器进行检查
	- 线程匹配：查找组内每个线程是否有特定的数据，并返回掩码
![GPGPU 笔记配图 20260326184949](/images/notes/gpgpu/20260326184949.png)

- 原子操作可以保证每次只能 有一个线程 对变量进行读写,其他线程必须等待,因此某一时刻存储器中的特定地址只能被 单一线程 所读写,这构建了基本的“锁”操作
- CUDA --> NVCC --> PTX --JIT--> SASS(SASS 与 计算架构相匹配)

## 线程分支
- 谓词寄存器：为每个通道配备1比特寄存器，用来控制通道是否开启
- 线程分叉点：由于分支语句，导致线程首次出现分叉的指令块（该指令块还没分叉）
- 线程重聚点：线程分叉后，首次恢复一致动作的指令块
- STMT堆栈：以栈的方式管理 活跃掩码，活跃掩码表示了该线程束内 活跃线程 的情况 --> 栈内每个条目包括 分支重聚点的PC（RPC）、下一条需要执行指令的PC（NPC）、线程活跃掩码
![GPGPU 笔记配图 20260403154106](/images/notes/gpgpu/20260403154106.png)
- 分支屏障-Yield指令：解决死锁问题，允许屏障中某些线程进入 让步 状态，让其他线程通过屏障执行下一条指令，从而释放资源解决死锁
	- 编译器在分支上显示插入yield指令 -->  交给工具链处理
	- 运行超时或执行了固定次数的会跳（从高PC进入低PC）触发 --> 交给**硬件**处理
- GPGPU通过串行执行发生分叉的线程来支持 条件分支，但会损失SIMT硬件执行效率
	- 寻找更早的分支重聚点 --> 直接线程后继重聚点并非最优
		- 结构化控制流：布尔运算中的短路优化
		- 局部重聚点（Thread Frontiers）：提前发现比IPDOM更优的重聚点 --> 编译器和硬件配合，编译器识别TF并插入重聚点检查，硬件保证线程执行顺序
			- 程序出现分支时，非活跃线程要在活跃线程的TF中等待
			- 有部分线程进入TF时，检查是否有线程可以合并
	- 线程动态重组和合并 --> 打破线程束静态构造，对特定互补的线程分片进行重组合并
		- 同线程束同PC的线程重组与合并 --> IPDOM重聚点
		- 同线程束不同PC的线程重组与合并 --> PC-Warp LUT建立线程与PC的映射关系
			- 动态线程束重组
			- 线程块压缩
			- 大线程束重组
		- 不同线程束同PC的线程重组与合并 --> 分支路径往往存在互补性
			- Simultaneous Branch Interweaving，允许`if`和`else`中的指令被一个线程束内的线程同时执行
		-  不同线程束不同PC的线程重组与合并

## 线程束调度
- 软件：调度算法/策略
- 硬件：调度器
两者协同，折中共同对 多个就绪状态的线程 进行调度
- SIMT 和 SIMD 的区别：
	- 多个线程聚集在一起 = 向量
	- 多个标量寄存器聚集在一起 = 向量寄存器
	- SIMT = 无需编程、基于硬件的SIMD/向量化
- 最终线程并行度 = 线程块、线程、寄存器和共享存储器中允许的最小并行度决定
- 线程发射停顿原因：
	- Pipeline busy，所需的功能单元忙
	- Texture，单元正忙
	- Constant，缓存缺失
	- Instruction Fetch，指令缓存缺失
	- Memory Throttle，大量存储访问操作未完成，可 合并存储器事务 缓解
	- Memory Dependency，请求资源不可用或满载
	- Synchronization，等待同步指令
	- Synchronization Dependency，输入依赖未解决
![GPGPU 笔记配图 20260514142003](/images/notes/gpgpu/20260514142003.png)
- 调度器调度策略：
	- 轮询（Round-Robin），依次轮询调用线程
	- 贪心（Greed-Then-Oldest），一个线程一直执行到不能执行为止
![GPGPU 笔记配图 20260514150223](/images/notes/gpgpu/20260514150223.png)
- SIMT的数据局部性：
	- 线程内局部性：由同一个线程束内的线程 再次访问
	- 线程间局部性：由不同线程束内的线程 再次访问
- 线程束调度优化：
	- 利用并行性掩藏长延时操作：两级轮询制度、线程块感知的两级轮询调度、结合数据预取的两级调度
	- 利用局部性提高片上数据复用：限流技术、CCWS（缓存局部性缺失，则提供更多的缓存资源----基于缓存资源的限流）、
	- 线程束进度分化与调度平衡：多调度器协调策略、线程束动态均衡调度策略

## 计分牌：用于规避数据冒险
### 数据相关性：
- 写后读RAW：真数据相关
- 写后写WAW：名称相关 --> 可通过 寄存器重命名消除
- 读后写WAR：反相关 --> 可通过 寄存器重命名消除

### CPU计分牌：
标记 指令状态、功能单元状态、寄存器结果状态，控制寄存器与功能单元之间的数据传送

### Tomasulo算法：
- 引入 保留站 对 寄存器动态重命名
- 引入 公共总线，允许操作数可用时，存储在 保留站 中，而不必等待寄存器写会

### GPGPU计分牌
GPGPU往往采用顺序执行的方式，避免乱序流水线带来的指令管理开销
- 计分牌为 每个线程束寄存器 分配 1比特 记录相应寄存器的写完成状态
- 若要往寄存器中写，则标记为 1 ，限制后续指令
当前计分牌的缺点：
- 大量的寄存器，使得计分牌所需的硬件开销巨大
- 线程调度时需要不断查询记分牌，计分牌需要端口供其查询，硬件开销巨大
计分牌优化设计：
- 基于寄存器编号索引的计分牌设计：NVIDIA专利（寄存器RID + 尺寸指示器）-->  通过寄存器编号 取代 独热码 --> 大幅减少硬件开销
![GPGPU 笔记配图 20260516182636](/images/notes/gpgpu/20260516182636.png){: width="697" }
- 基于读写屏障的软件计分牌设计:
	- NVIDIA的GPGPU软件计分牌：基于编译器实现的
		1. 显式将寄存器绑定到某个读/写屏障上，写屏障解决RAW、WAW冒险，读屏障解决WAR冒险
		2. 目的寄存器的写操作直接设定在读写屏障上
		3. 源操作寄存器通过读写屏障，获取写操作是否完成

## 线程块分配与调度
### 线程块并行、分配与调度
- 线程块由 一个 或 多个 线程束组成的
- 线程块之间相互独立、不存在依赖关系
- 基本的调度粒度：线程束
- 线程块的调度与初始线程的分配也密切相关

### 基本的线程块分配与调度策略
线程块的分配和调度是 GPGPU 硬件多线程执行的前提
#### 线程块的分配策略
- 轮询：为每个可编程处理器都至少分配 一个线程块，有资源剩余则进行下一轮
	- 可能破坏线程块之间的 数据局部性
- 千兆线程引擎（NVIDIA）：大体遵循轮询，但会考虑两个SM组成的纹理处理簇（TPC）
- 线程块不允许任务抢占 和 迁移

#### 线程块的调度策略
- 轮询：公平的最大并行可能性，但缺乏局部性优化
- GTO：按照贪心策略，一直到该线程块无法执行为止，缺乏调度公平性，导致无效线程

#### 线程块分配与调度策略
- 感知空间局部性的调度策略
	- 感知 L1缓存 局部性的块级线程块调度 --> 轮询调度破坏线程块空间局部性
		- 块级线程块调度：在一个核上运行多个连续线程块 --> 线程块执行速度可能不同，加入 **延迟** 策略对齐
		- 连续线程块感知：线程 **束** 调度时兼顾线程 **块** 调度 --> 让连续线程块中的线程束有最大的并行度
	- 感知DRAM板块的线程块协同调度：不同核上的连续线程块同时访问同一个DRAM块的不同位置时，易出现冲突
		- 将DRAM行缓冲区中，未被访问到的数据预取读入L2缓存中
![GPGPU 笔记配图 20260531112654](/images/notes/gpgpu/20260531112654.png)
- 感知时间的局部性的抢占调度策略 --> L1数据缓存命中率和复用率较低
	- 允许再次就绪的线程块 抢占 正在执行的线程块
![GPGPU 笔记配图 20260605111457](/images/notes/gpgpu/20260605111457.png)
- 限制线程块数量的怠惰分配和调度策略
	- 监视：记录每一个线程块发射指令的个数
	- 节流：计算每个 可编程处理器 更为合理的线程块个数
	- 怠惰执行：为每一个内核函数重新分配线程块数量，同一个内核函数可以在不同的处理器上分配相同的线程块数量，不同的内核函数则要重新计算
- 利用线程块重聚类感知局部性的软件调度策略
	- 可利用局部性（算法相关、缓存行相关）：通过聚类挖掘线程块的局部性
	- 不可利用局部性（数据相关、写相关、流）：重新构建线程块执行顺序

## GPGPU存储系统
GPGPU遵循 吞吐率 优先的原则
![GPGPU 笔记配图 20260606214848](/images/notes/gpgpu/20260606214848.png)
- 寄存器文件最大，是为了满足 线程束之间的零开销切换，通过线程束之间的切换掩盖访存延迟
- GPGPU的缓存容量小，更需要精细化管理
- GPGPU访存是 高度并行化的 --> 需要专门的 访存合并单元 对线程访存请求进行合并

## 寄存器文件
#### 并行多板块结构
GPGPU通过多个板块（Bank）的单端口SRAM 来模拟多端口的访问
![GPGPU 笔记配图 20260606223100](/images/notes/gpgpu/20260606223100.png)
![GPGPU 笔记配图 20260607164236](/images/notes/gpgpu/20260607164236.png)
- 每个逻辑Bank 会被拆分为 更小的 物理板块
- 线程束内所有线程的寄存器 打包为 线程束寄存器 统一读取和写入
#### 板块冲突与操作数收集器
当多个请求进入同一个逻辑Bank内，出现 Bank冲突，仅能依次串行访问

##### 操作数收集器：
![GPGPU 笔记配图 20260607165549](/images/notes/gpgpu/20260607165549.png)
- 一个有效位，表示指令是否含有该 操作数
- 一个寄存器RID
- 一个就绪位，表示寄存器是否被读取（操作数字段是否有效）
- 操作数字段，长度可以保存一个 线程束寄存器
- 收集单元还会记录 当前的线程束WID

##### 寄存器的板块交错分布
线程束的基本调度策略是 轮询，只要线程束就绪，会发射 不同线程束中相同PC的指令（WID不同但RID相同） --> 改变寄存器在板块内的分布来避免 Bank冲突
![GPGPU 笔记配图 20260609153242](/images/notes/gpgpu/20260609153242.png)
- 将不同线程束同一编号的寄存器交错放在不同的Bank中 --> 消除访问相同寄存器编号产生的冲突
#### 操作数并行访问时的相关性冒险
- 每个线程束最多执行一条指令
- 每个线程束仅允许一条指令在操作数收集器中收集数据
#### 寄存器文件的优化设计
重点在于 降低功效、优化延迟访问 和 平衡带宽
##### 增加前置寄存器文件缓存
40%的数据仅被读取一次 --> 通过寄存器缓存（RFC）捕捉短生命周期的数据，减少对主寄存器的访问
![GPGPU 笔记配图 20260609161430](/images/notes/gpgpu/20260609161430.png)
- 线程被划分为 活跃线程 和 挂起线程，仅活跃线程拥有 RFC 资源
- RFC可以降低寄存器整体的能耗，并减少Bank冲突
##### 基于嵌入式动态存储器（eDRAM）的寄存器文件设计
GPGPU的工作频率仅有 1Ghz，eDRAM的速度满足要求，且其容量更大
![GPGPU 笔记配图 20260609165140](/images/notes/gpgpu/20260609165140.png)
- eDRAM需要经常刷新，刷新操作成为其片上设计的主要瓶颈 --> 如何隐藏刷新开销
	- 发生Bank气泡时，对Bank执行刷新策略，长时间无气泡则整体刷新一次
	- 写操作时自带天然刷新
##### 利用数据压缩的寄存器文件设计
一个线程束内所有线程所读写操作数的值差距很小（值相似）
![GPGPU 笔记配图 20260609170504](/images/notes/gpgpu/20260609170504.png)
- GPGPU中很多局部数据是基于 线程ID 产生的，连续的线程ID 相差1
- 运行时输入数据的动态范围往往很小
- 选择线程束中的一个线程寄存器作为 基值（Base），计算其他寄存器相对于Base的差值（Delta）
- 写回寄存器前进行压缩，读取寄存器前进行解压，减少激活的寄存器Bank数降低功耗
##### 编译信息辅助的小型化寄存器文件设计
基于编译器信息，仅维护代码所需的少量寄存器，用小容量的OSU（operand staging unit，操作数暂存单元）替代大容量寄存器
- 中间寄存器：一次性寄存器、程序控制相关寄存器
- 长时间寄存器：数值输入寄存器、存放结果寄存器
## 可编程多处理器内的存储系统
#### 数据通路概述
![GPGPU 笔记配图 20260609173028](/images/notes/gpgpu/20260609173028.png)
- 可编程处理器内 局部的 数据缓存：如 L1缓存，可以与共享存储器（shared/local memory）共享一块存储区域
- 可编程处理器外 共享的 数据缓存：如 L2缓存
##### 共享存储器访问
- Load/Store单元独立判断是否有共享存储器的Bank冲突
- 共享存储器的地址是由编程人员 显示控制的，且为直接映射
- 重播（Replay）机制 --> 应对Bank冲突问题，仲裁器对请求进行划分
	- 不含Bank冲突的请求子集：无冲突正常执行
	- 其余请求：退回指令流水线，稍后重新发射（重播），指令保存在指令流水线的缓存中，也可在Load/Store单元中设置缓存空间存储

#### L1 高速缓存访问
##### L1 数据访存的读操作
- 行大小 = 共享存储器的访问宽度，通常为128字节
- 命中则写入寄存器
- 未命中则重播，MSHR（Miss Status Holding Register，不让整个Cache停下）与下一级存储结构交互 --> 非阻塞式缓存缺失的处理机制与结构
##### L1 数据访存的写操作
- 现写入 数据缓冲器中，再由数据交叉开关统一写入SRAM
- L1 Cache一般没有保证一致性
	- 对于线程私有数据：写回
	- 对于全局存储器：写驱逐，写入 L2后让 L1中 Cache 置无效
	- 对于写缺失：可以采用写不分配

## 可编程多处理器外的存储系统

#### 存储分区单元
![GPGPU 笔记配图 20260723160109](/images/notes/gpgpu/20260723160109.png)
- L2 Cache：缓存数据，对L1 中的所有数据都进行缓存
- 帧缓存：对 全局存储器器的访问请求进行重排序
- 光栅化单元：原子操作处理、纹理数据处理

#### L2 Cache
一端连着SM，一端连着全局存储，是GPGPU的最后一级缓存（Last Level Cache，LLC）
- 每个分区单元由两个 slice 组成
- 向外部的写请求都是合并issue的
- 写缺失时采用写不分配police
#### 帧缓存单元
- 负责 存储访问调度器，减少DRAM的行切换动作
- 读请求会合并读取，尽可能读取DRAM的同一行，减少行开启的大量耗时
#### 全局存储器
##### 图形处理器件
- 采用GDDR，一种特殊类型的DRAM，接口扩展至 32位，管脚频率变高
- 存储访问请求经重排汇聚后，一次性传输
##### 全局存储器的访问方式
- 请求合并：将一个线程束中多个线程对 同一个地址 的请求合并 --> 专属硬件处理
- 地址对齐：请求从特定地址开始，才能连续访问，从而有更高的访问效率
